# Algorithm inventory

Generated by `python optimization/make_inventory.py`. Every column is
measured: loop structure and numerical call sites come from the AST audit
(`audit_static.py`), baseline timings from the survey sweep
(`optimization/benchmarks/results.csv`, `implementation == survey`,
n = 200, d = 8, k = 3, single fit).

`Baseline` is blank where the estimator is not in the harness registry —
it takes an input shape the shared registry does not build (see
`optimization/harness.py`). Those are audited statically but not timed.

**Implementation provenance.** Every algorithm in SCPP is a direct,
SCPP-specific implementation of its published method written against
NumPy/SciPy. None wraps a third-party estimator, and none is a vendored
copy of reference code; `scikit-learn` is used only for supporting
primitives (DBSCAN, KMeans, eigen-solvers) inside some methods.

## Coverage of this study

- Algorithms exported by SCPP: **40**
- Statically audited: **40**
- Baseline-timed in the survey: **28**
- Profiled in detail: **10**
- Optimized, verified and benchmarked end to end: **2**

The gap between *profiled* and *optimized* is deliberate and is discussed
in the report under 'Algorithms not optimized' and 'Limitations'.

## Notes on untimed algorithms

`AFCMAdaptive`, `SKFCM`, `RDFKC` (image inputs), `BGMM` (two aligned
views), `SoftKSC` (labelled and unlabelled parts), `FeMIFuzzy` (a list of
client matrices), `LDA` (returns factors rather than a partition) and the
four PyTorch estimators `CDCGS`, `DMoN`, `MMSB`, `NOCD` are excluded from
the shared harness for the same reasons `tests/test_protocol.py` excludes
them. `BIGCLAM` requires `n_nodes` at construction and is registered but
was not timed in this survey.
